# General Guidelines for working with Nx

- For navigating/exploring the workspace, invoke the `nx-workspace` skill first - it has patterns for querying projects, targets, and dependencies
- When running tasks (for example build, lint, test, e2e, etc.), always prefer running the task through `nx` (i.e. `nx run`, `nx run-many`, `nx affected`) instead of using the underlying tooling directly
- Prefix nx commands with the workspace's package manager (e.g., `pnpm nx build`, `npm exec nx test`) - avoids using globally installed CLI
- You have access to the Nx MCP server and its tools, use them to help the user
- For Nx plugin best practices, check `node_modules/@nx/<plugin>/PLUGIN.md`. Not all plugins have this file - proceed without it if unavailable.
- NEVER guess CLI flags - always check nx_docs or `--help` first when unsure

## Scaffolding & Generators

- For scaffolding tasks (creating apps, libs, project structure, setup), ALWAYS invoke the `nx-generate` skill FIRST before exploring or calling MCP tools

## When to use nx_docs

- USE for: advanced config options, unfamiliar flags, migration guides, plugin configuration, edge cases
- DON'T USE for: basic generator syntax (`nx g @nx/react:app`), standard commands, things you already know
- The `nx-generate` skill handles generator discovery internally - don't call nx_docs just to look up generator syntax

# Billy project conventions

Nx + pnpm monorepo. Everything above this section is managed by Nx; edit only below.

## Layout

| Path              | Stack                                                                          | Nx tag         |
| ----------------- | ------------------------------------------------------------------------------ | -------------- |
| `apps/api`        | NestJS 11, webpack, global prefix `/api`, port 3000                            | `scope:api`    |
| `apps/worker`     | NestJS application context (no HTTP), BullMQ consumer planned                  | `scope:worker` |
| `apps/web`        | Next.js 16 (App Router, `output: standalone`), React 19, HeroUI v3, Tailwind 4 | `scope:web`    |
| `packages/shared` | Types/zod schemas shared by everyone                                           | `scope:shared` |
| `packages/db`     | Postgres (pgvector) access                                                     | `scope:db`     |
| `packages/ai`     | Anthropic/LLM logic                                                            | `scope:ai`     |
| `infra/local`     | Docker Compose for local dev                                                   | –              |

Allowed dependencies (enforced by `@nx/enforce-module-boundaries` in `eslint.config.mjs`):
`api`/`worker` → shared, db, ai · `web` → shared only · `ai`/`db` → shared · `shared` → shared.
Never import `db` or `ai` from `web`. When adding a tag or rule, update `eslint.config.mjs`.

## Conventions

- Use `pnpm` (never npm/yarn). Run tasks through Nx: `pnpm nx <target> <project>`.
- Libs are named `@org/<name>`, consumed as workspace packages (`"main": "./src/index.ts"`); wire them with
  `pnpm add @org/<name> --workspace --filter @org/<consumer>`, never with tsconfig `paths`.
- Project config lives in each `package.json` under the `nx` key (no `project.json`).
- Prettier: single quotes. Commits: Conventional Commits (`feat(infra): ...`), English.
- Config comes from env vars (`.env.example` is the source of truth; `.env` is local, never commit it).
  Compose passes container-internal hosts; `.env` uses `localhost` for apps run on the host.
- Docker images are Nx targets (`docker:build`), tagged `apps-<name>`; compose uses `pull_policy: never`.
- Local S3 is SeaweedFS (S3 API only). Do not use SDK features that are not S3-compatible.
- Docs for the local stack are in `infra/README.md`; keep it in sync when changing compose, scripts or ports.

## Local stack

`pnpm start` (build images + up + watch) · `pnpm start:detached` · `pnpm stop` · `pnpm reset` (wipes data) ·
`pnpm logs` · `pnpm infra:up|infra:down` (only Postgres/Redis/S3, apps run with `nx serve`) ·
`pnpm db:migrate` (TypeORM migrations in `packages/db`) · `pnpm openapi` (regenerate `apps/api/openapi`).
